# Security policy

This is a pre-alpha prototype. Do not use it for safety-critical, medical, financial, laboratory-control, or autonomous experimental decisions.

Scientific documents are untrusted input. The funded implementation should isolate parsers, reject executable content, cap document and image sizes, avoid loading active attachments, and require explicit permission before any remote request. Secrets must not appear in run manifests or public examples.

An extracted record reports what the software found in a source. A `valid` schema result does not mean the scientific claim is true. Human review, uncertainty, and source inspection remain required.

Use GitHub's private vulnerability-reporting channel for this repository when it is available. If that channel is unavailable, contact the maintainer through the GitHub profile before sending details. Do not place confidential documents, credentials, or unpublished exploit details in a public issue.
